A number on a diagnostic screen is useful only when you know whether the car returned it, when it was read and whether the app can interpret it confidently. Check those details before acting on a result.

## Check what answered

A scan may be complete, partial or unsupported for a particular vehicle. Where the screen provides coverage, compare the number of requested readings with the number returned. A missing response is not zero. A control unit that does not answer could be absent from that vehicle, asleep, busy or unreachable; one silent scan cannot tell you which.

The app may distinguish **measured** values from values **calculated** from other readings. A provisional interpretation means the decoder needs more verification. Neither a provisional value nor a missing value should be treated as proof of a fault or proof of good health.

Some figures carry an explicit **likely** label (drive-unit and DC/DC operating hours, learned consumption bands) because the value is real but its unit or scale has not yet been confirmed against the car. Histograms whose bin edges are not established show numbered bands instead of percentages or temperatures. A "likely" label is not noise to ignore: it is the difference between a checked number and an unchecked one. Where a group decodes only part of what the module returned, the status line says so outright, for example *"12 of 70 values read."*

## Check when and how it was read

A saved session shows what the car reported when that session was captured. Live Data shows newer samples while a stream is running. Compare readings under similar conditions: battery charge level, temperature, driving state and charging state can change the numbers. Repeating a surprising measurement is often more useful than treating one scan as final.

## Use comparisons carefully

Cross-checks compare related values, such as pack voltage with the sum of cell voltages or charge figures from different units. The app runs a wider set of these than one page shows: the same odometer read from several modules, one vehicle clock compared across modules, the 12 V supply read from every module that reports it (with each module's known reading offset taken out), battery temperature and pack voltage compared between the thermal manager and the battery module, and the displayed charge level against the energy remaining. The Cross-Check screen shows the expected and observed numbers behind each verdict instead of the verdict alone.

Agreement increases confidence in a reading, but it does not prove every sensor is correct. A disagreement can reflect timing, an incomplete read or a real issue. Read the coverage and the individual values before deciding what to investigate next.
