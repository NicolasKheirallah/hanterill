Versions follow [SemVer](https://semver.org/). A release is a tag in the app repository, and the
notes for every version live with that version, rendered on the [changelog page](/changelog).

## Where to find things

- **[Changelog](/changelog)**: the notes for each version, rendered on this site.
- **[Releases](https://github.com/NicolasKheirallah/hanterill/releases)**: tagged builds with
  installers and a checksum file. The [download page](/download) reads the latest release live from
  GitHub.

## What a version contains

Release notes keep the same split between verified and unverified that the rest of the site uses:

1. What is **verified** on a tested platform (CMA today).
2. What is **catalogued but unverified** for other platforms (SPA and SEA1 at the time of writing).
3. What is **research**: captures, provenance documents and open questions.

A decoder that has not been confirmed against hardware ships with that label, and the runtime
capability manifest reports the difference. Compatibility work never becomes a claim of
support without the evidence.

## Artifacts and verification

The assets vary by release. The release page lists the files actually published for each OS and
architecture. Use [Install on your computer](/docs/installation) to choose one. When a release
includes `SHA256SUMS.txt`, compare the checksum for the exact file before running it.

<Callout kind="caution" title="macOS signing status">
macOS builds are ad-hoc signed only, which means Gatekeeper will not vouch for them. The first
launch needs a right-click and Open, or a one-time quarantine clear. Windows builds are unsigned
too, so SmartScreen may warn. Check the checksum file if that matters to you.
</Callout>

## Updates

**Settings → Updates** has **Check now** and an optional check on launch. The launch check is off
by default and runs at most once a day when enabled. It looks up the latest published release on
GitHub and shows a notice if it is newer. Hanterill does not download or install it; use the
[download page](/download) or the release page yourself. See [Privacy](/docs/privacy) for the
network request. If you installed on Linux from a package manager, update through that manager.

Your stored sessions survive an update: the session format is versioned, and a newer schema opens
read-only in an older build rather than being rewritten.
