Hanterill was built CMA-first. The Compact Modular Architecture platform, under the Polestar 2
and the smaller electric Volvos, is where the battery, ECU and routine coverage was written and
checked against a real car. Other platforms are in progress, and this page says exactly how far
each one has got.

## Reachable is not the same as supported

Two different things, and the difference matters:

- **Reachable** means Hanterill can get a connection to the car over DoIP.
- **Supported** means the diagnostic functions are written and checked against known-good
  readings.

A car can be reachable and still tell you almost nothing useful. The decoder that turns raw bytes
into a battery percentage has not been written or verified for that platform yet. The labels on
this site always describe the second thing.

## What the labels mean

| Label | Meaning |
| --- | --- |
| Supported | Verified against a live car. Battery, fault codes, ECU identification and live data are exercised regularly. |
| Partial | Some functions verified, others not covered yet on this model. |
| Testing | The code exists but still needs testing on more cars. Treat every reading as provisional. |
| Research | We are still figuring out how the platform works. Not usable for diagnostics. |

The tested platform. Polestar 2 and the CMA Volvos share one high-voltage layout, so a feature

### SPA

Partially supported. Ships as catalogue data: pack topologies, a CAN-era BECM registry and
decoders. The hybrid and EV battery path still needs testing on more cars. On first-generation SPA
the battery answers over older CAN wiring. An ISO-TP CAN transport is implemented in the app, but no
hardware adapter ships yet, so live battery scanning waits on that adapter, not on software that does
not exist.

<Callout kind="caution" title="Battery path needs more cars">
The SPA battery definitions still need testing on more cars before you rely on the figures.
</Callout>

<PlatformSupport platform="SPA" />

### SEA1

The EX30-class definitions exist in the catalogue: ECU registry, routing addresses, identifier
maps and cell mapping. Every one of them still needs testing on more cars. The platform is called
SEA1 in the app; "SEA" is the family name.

<Callout kind="caution" title="Needs testing on more cars">
SEA1 ships as definitions that still need testing on more cars. Zeekr and other sub-platforms
deliberately do not inherit the EX30 map, because family resemblance is not evidence.
</Callout>

<PlatformSupport platform="SEA" />

### SPA2

Under investigation. The gateway and security model work differently, and no implementation has
been tested on a car yet.

## Battery pack layouts

The cell matrix takes its shape from the catalogue, never from a number written into the code.
Each pack layout records how many cell groups it has and how they are arranged:

| Platform | Layout | State |
| --- | --- | --- |
| CMA | 108 groups: 27 modules of 4 (78 kWh) | Verified on the reference car |
| CMA | 108 groups: 27 modules of 4 (82 kWh) | Catalogued from catalogue and decoder evidence |
| CMA | 96 groups: 24 modules of 4 (69 kWh) | Defined from catalogue and decoder evidence |
| SPA | 96 (69 kWh), 108 (78 kWh), hybrid 102 (T8) | Catalogued, needs testing on more cars |
| SPA | hybrid 96 (early T8, 11.6 kWh) | Catalogued, needs testing on more cars |
| SEA1 | 107 (69 kWh NMC), 120 (51 kWh LFP) | Catalogued, needs testing on more cars |
| SEA1 | 110 (100 kWh NMC, Zeekr-class) | Catalogued, needs testing on more cars |

A pack is judged complete at its own cell count. A 102-cell hybrid is never marked incomplete for
not having 108.

endorsement. Hanterill is an independent project and is not affiliated with Volvo Cars, Polestar
or Geely.
